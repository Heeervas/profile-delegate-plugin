## Architectural decisions to test before code

1. **Steer is a requirement, not optional polish.** Background `auto` stays TUI/interactive; `simple` is explicitly non-steerable. For this implementation, `auto` fails closed on TUI startup failure; no automatic CLI fallback. An explicit `simple` request may run without steer. A later fallback proposal needs proof it is before any `prompt.submit` write (not merely before its ACK), and must return `selection_pending` at dispatch until resolved. A timeout/EOF on submission is ambiguous and never retried through another transport. Persist requested, selected, and actual transport separately.
2. **Reuse Hermes steering runtime without borrowing its guarantees blindly.** `/opt/hermes/agent/interrupt_control.py` owns `AIAgent.steer`, `/opt/hermes/agent/agent_runtime_helpers.py` drains at a safe boundary, and `/opt/hermes/tui_gateway/methods_session.py` exposes `session.steer`. Native `/opt/hermes/tools/delegate_tool_registry.py` has atomic close and `missed_steer`, but that is a separate in-process registry. Profile Delegate's `session.steer` RPC only proves queued/rejected, not delivery or a command ID. A per-command `delivered` state requires an authoritative correlated child event; if no public plugin-observable seam exists, terminal accepted-but-unconfirmed steers remain `unknown`, not `missed` or `delivered`. Inspect `/opt/hermes/tui_gateway/prompt_turn.py` late-steer requeue; test whether a late correction launches a subsequent turn and prevent falsely marking the parent run terminal before that turn is accounted for. Do not patch `/opt/hermes` or invent a second agent-turn injector.
3. **Environment ownership.** Trace and sanitize one bounded environment snapshot across `core._start_detached_background_worker` → `core.child_environment` → `tui_runner._environment`/CLI bootstrap → Hermes config loading. Scrub inherited execution-specific variables at worker creation and child construction, preserving only explicitly documented provider credentials and host routing/proxy requirements; profile-local `.env`/config retains precedence for profile policy. Record variable names and source, never values. Distinguish requested, preflight-resolved, and runtime-observed capabilities; where Hermes cannot expose the loaded surface, report `unknown`, not a guessed effective list. Test hostile parent overlays on foreground CLI, detached CLI, and detached TUI.
4. **Same-profile recursion.** Trace actual lock roots and process ownership. Reject only recursive same-home edges that would deadlock; a top-level call to the current profile, if otherwise authorized and capacity permits, need not be arbitrarily banned. If safe same-profile recursion is a required workflow, evaluate lineage-aware permits rather than raising global concurrency. Never claim profile homes are security sandboxes.
5. **Authority compatibility is a prerequisite, not a late polish gate.** Exact-origin authorization for model-facing status/list/control and maintenance must be established before any functional version is accepted. The existing CLI only provides `watch` and `inspect`; do not claim it can reconcile/prune. Add a separate operator-only CLI inspect/list/reconcile path before restricting model tools, confined to local same-UID operator invocation with an explicit `--runs-root`/home and no model-facing bypass parameter. Same-UID CLI is an operator boundary, not an OS security sandbox; legacy artifacts missing origin remain readable through this CLI but are denied from model-facing origin reads unless positively correlated. Reconcile never deletes; prune remains separately approval-gated. Existing callers that depend on global model reads must be inventoried before activation.
6. **Approval trust source.** Model-callable `approve_yolo` is not proof of Alberto's authorization. Default model-supplied elevation to **off**; retain a target-profile/operator-configured approval policy where presently allowed, without allowing a request field to elevate above it. A true per-run exception requires a separately approved immutable scoped expiring operator grant with non-forgeable validation; **do not implement such a broker in this project without separate authority**. Audit current consumers and migrate any legitimate per-call elevation to explicitly configured operator policy before activation, or leave activation blocked. This narrows privilege; it does not change credentials or live config in this implementation.
7. **Schema compatibility.** Existing flat `profile_delegate` calls remain accepted except a previously permitted model-supplied authority elevation, which must fail with a specific migration path. Add a bounded request-specific preflight and clear descriptions/default semantics first; introduce a versioned grouped request only if current contract genuinely needs it. Avoid parallel generic adapters and invented configuration.

### D — Steer-first transport and delivery evidence

- **Write:** `core.py`, `tui_runner.py`, `tui_rpc.py`, control/event tests; after C.
- **Evidence:** background auto remains steerable or fails closed; explicit `simple` is non-steerable. Requested/selected/actual transport are persisted and status readback reflects actual steerability, while detached dispatch reports `selection_pending` until worker confirms it. Exact-origin controls, concurrent steer-vs-final race, process death, RPC rejection/timeout and late steer requeue are tested. `queued`, `delivered`, `missed`, and `unknown` remain distinct: only emit delivered/missed with correlated proof, otherwise terminal unknown. Compare live TUI and CLI startup/latency/RSS with the same harmless task; size any new deadline from legitimate measured startup. Preserve cancellation/reaping and notification. A submit timeout/EOF is ambiguous: no cross-transport retry.
- **Detached simple cancellation contract (D narrowed at the pre-identity seam):** before the worker publishes a verifiable owned group identity, cancellation explicitly refuses with `control_identity_pending` and creates no command or ACK; the caller may retry after identity is published. This avoids signaling an unknown PID or falsely claiming that an intent survived worker death in either spawn-to-identity gap. After identity publication, exact-origin control writes target the owned detached CLI worker; identity includes PID plus recorded process start/group identity. A changed/dead/unverifiable identity refuses with `control_identity_unverifiable`; ACK is issued only after the owned CLI leader is reaped, and terminal `cancelled` follows verified cleanup. Process death/timeout is not successful cancellation. Steer fails before/at dispatch with `control_unavailable_simple_transport`; do not fabricate interactive ACKs.
- **Rollback:** additive selector for new runs only; do not migrate/kill active runs.
